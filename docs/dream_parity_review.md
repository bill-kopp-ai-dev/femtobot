# Dream Consolidation — Parity Review Findings (v0.1.4)

Findings from the eighth-pass parity review of the Dream consolidation
system against the upstream nanobot project (the fork origin).
The Femtobot runtime is a deliberately simplified subset of nanobot,
but several Dream-related features were lost during past refactors
that the audit team did not later restore.  This document captures
those gaps so a future round can close them.

Severity reflects the user-facing impact, not the line count of the
missing code.

## Scope

> **Status (v0.1.5):** all six regressions (R1-R6) are now closed
> in v0.1.5.  See the test suite ``tests/test_dream_parity.py`` for
> per-finding regression coverage.  The three Femtobot-specific
> evolutions (F1-F3) are preserved.

The comparison touched:
- `nanobot/agent/memory.py` (MemoryStore + Consolidator) ↔
  `femtobot/agent/memory.py`
- `nanobot/agent/autocompact.py` ↔ `femtobot/agent/autocompact.py`
- `nanobot/command/builtin.py` (`/dream` command) ↔
  `femtobot/command/builtin.py`
- nanobot's `tests/agent/test_dream*.py` (5+ files) ↔
  `femtobot/tests/test_memory_a6_a7_a10.py` (1 file, 5 tests)

## Regressions found

### R1 (HIGH) — `build_dream_prompt` no longer embeds current durable files

**Nanobot** embeds the current contents of SOUL.md, USER.md, and
memory/MEMORY.md as a `## Current Memory Files` section inside the
Dream prompt, via `_render_current_memory_files()`.  The upstream
comment spells out why:

> "The current contents of the durable memory files (SOUL.md, USER.md,
> memory/MEMORY.md) are embedded so the model edits the real files
> rather than a stale mental model — eliminating a class of
> failed/out-of-bounds edits that previously produced hallucinated
> audit records."

Femtobot's `build_dream_prompt` (in `femtobot/agent/memory.py`)
omits that section, so the Dream run edits against a stale baseline
and can produce out-of-bounds edits.

### R2 (HIGH) — `dream_content_diff` removed; cursor advance uses LLM self-report

**Nanobot** computes a `dream_content_diff()` from the git
working-tree delta of the durable files.  The `/dream` command then
gates cursor advance on real edits:

```python
diff_body = store.dream_content_diff()
productive = bool(diff_body) or (
    not store.git.is_initialized()
    and MemoryStore.dream_run_completed(resp)
)
if productive:
    store.set_last_dream_cursor(last_cursor)
```

Femtobot gates cursor advance only on the LLM's self-report via
`dream_run_completed(resp)`.  When the LLM runs to completion
without editing anything (a perfectly valid "no work to do" outcome)
the cursor still advances because the gate is too permissive, and the
next cycle silently skips those history entries.

### R3 (HIGH) — `_has_compactable_idle_tail` removed from autocompact

**Nanobot** uses two guards before archiving an idle session:

```python
if self._is_expired(updated_at, now) and self._has_compactable_idle_tail(key):
    self._archiving.add(key)
```

`_has_compactable_idle_tail()` checks that the unread tail contains
at least one message newer than `last_consolidated`.  Femtobot
collapsed the guard to a single check, so sessions that are
"expired" but contain nothing new (e.g. fully consolidated sessions
that get touched by the heartbeat task) get archived redundantly,
wasting Consolidator cycles.

### R4 (MEDIUM) — `read_recent_history_for_prompt` removed

Nanobot filters unprocessed history entries by session classification
(`_INTERNAL_HISTORY_SESSION_KEYS = {"heartbeat"}`,
`_INTERNAL_HISTORY_SESSION_PREFIXES = ("cron:", "dream:")`) so the
Dream run does not pick up entries generated by other internal
sessions.  Femtobot removed both the helper and the classification
constants, so internal sessions leak into the Dream history tail.

### R5 (LOW) — `_DREAM_FILE_EMBED_CAP` truncation removed

Closely tied to R1.  When R1 is restored, the embed code will need
the 8000-char per-file cap with rate-limited warning that nanobot
provides via `_render_current_memory_files()`.

### R6 (LOW) — `_DREAM_PROMPT_MAX_CHARS` truncation removed

Nanobot's `_dream_template()` truncates a workspace override prompt
at `_DREAM_PROMPT_MAX_CHARS` with rate-limited warning.  Femtobot
removed `_dream_template`, `dream_prompt_file`,
`has_dream_prompt_override`, and `default_dream_prompt` together, so
the truncation is moot today but will need to be reintroduced
alongside the override path.

## Where Femtobot EVOLVED past nanobot

The picture is not all regressions.  The Femtobot runtime added three
behaviors nanobot does not have, all addressing known failure modes:

- **F1** `advance_dream_cursor_after_commit(cursor, *, commit_message)`
  in `femtobot/agent/memory.py` couples cursor advance to a
  successful git commit.  Nanobot advances the cursor *before*
  attempting the commit, which can lose work on a crash.  Closing
  R2 should preserve this seam.
- **F2** `set_last_dream_cursor` uses `atomic_write_text`
  (`tempfile` + `os.replace`) instead of plain `write_text`.  Trivial
  diff but eliminates a class of partial-write corruption.
- **F3** `_enforce_monotonic_cursor` rejects cursor regressions from
  external writers (editors, scripts).  Pinned by
  `test_enforce_monotonic_cursor_*` in `test_memory_a6_a7_a10.py`.

A future round that restores R1/R2 should not regress these three.

## Test coverage gap

| Area | nanobot | Femtobot |
|------|---------|----------|
| test files | 5 (`test_dream.py`, `test_dream_session.py`, `test_dream_tools.py`, `test_dream_config.py`, `test_builtin_dream.py`) | 1 (`test_memory_a6_a7_a10.py`) |
| test count | dozens | 5 |

The 5 Femtobot tests cover atomic cursor write, monotonic cursor
enforcement, and malformed JSONL lines (A6, A7, A10).  There are no
tests for `build_dream_prompt`, `dream_content_diff`,
`read_recent_history_for_prompt`, or the integration test path that
exercises git commit + cursor advance together.
